# Jarvis v0.3.25

Cumulative Windows release containing the complete v0.3.23 and v0.3.24 feature/reliability work plus the v0.3.25 regression fixes below. Installing v0.3.25 is sufficient; v0.3.23 and v0.3.24 do not need to be installed separately first.

## Included from v0.3.23

- Route ordinary typed and voice conversations through the conversation-origin path so normal chat no longer repeatedly triggers the external-AI confirmation flow.
- Support up to 20 chat attachments/images with the existing 1 GiB selected-data ceiling and client-side image optimization.
- Add attachments to the command-center chat and retain attachment metadata in conversation history/offline snapshots.
- Keep the chat-history drawer above desktop navigation so it is not hidden by the left sidebar.
- Fix manual Self-Repair plan persistence and natural Hungarian repair-command recognition.
- Keep the visible Accept button as the final owner approval for the exact hashed repair proposal while preserving owner, expiry, source-fingerprint, backup, validation and rollback protections.
- Keep System Center under Tools in mobile navigation.
- Keep build-only Tailwind tooling out of production dependencies and retain behavior-based Self-Repair UI tests.

## Included from v0.3.24

- Add owner-controlled GitHub Self-Repair connection with the fine-grained token protected by Electron safeStorage and not exposed to the AI or renderer status.
- Create minimal exact-hash repair plans and validate approved source in isolated staging after a clean dependency install, complete source tests, lint, typecheck, policy checks and renderer build.
- Restore staging before publishing validated changes to a dedicated GitHub repair branch/PR; never activate an unverified local runtime.
- Protect trust-core, release tooling, CI workflows, version metadata and existing tests from AI-authored repair patches.
- Reject unsafe path aliases, verify reused repair branches and require exact approved diffs.
- Verify independent CodeQL and Windows CI at the exact PR head and refuse merge when the original main head changed.
- Keep abandon, merge and release as separate owner-controlled operations and bind release publication to the exact merged main SHA/version.
- Validate release manifest, installer version, SHA-256 and immutable release target before update handoff.
- Show GitHub connection, repair PR, CI and update state in System Center.

## v0.3.25 regression fixes

- Smart-device control now separates HTTP transport success from verified physical state. Contradictory, malformed, empty or unknown device responses cannot persist the requested ON/OFF state or produce a completed action log.
- Scene and routine completion now treats an unverified physical-device step as a failed partial step instead of reporting the overall operation as completed.
- Recorded microphone capture now isolates async work by capture generation. A stale getUserMedia rejection, recorder callback, AudioContext continuation or STT callback cannot stop or corrupt a newer recording session.
- Route offline sync now schedules bounded automatic backoff retries with one worker, restores interrupted work after restart, preserves per-route start → update → end ordering, does not consume retries while offline, and retains exhausted items for manual recovery.
- User-visible JSON examples that contain fields such as tool, params or tool_calls are preserved in normal text/JSON code blocks and remain non-executable. Real internal actions still require the trusted internal response envelope/actions context and remain filtered from display.
- Add dedicated regressions for all four reproduced v0.3.24 edge cases while retaining the existing test suite and security/policy gates.

## Verification

The release candidate must pass CodeQL, JavaScript syntax checks, full source parsing, the complete source-test suite, lint, TypeScript typecheck, production dependency audit, verify:jarvis, renderer build, Self-Repair toolchain staging, Windows NSIS installer build, packaged Self-Repair verification, admin-helper handshake, Windows startup smoke test, checksum and release-manifest verification.

Mock tests do not prove real physical-device or real microphone-hardware behavior. Those paths still require hands-on Windows/hardware acceptance testing.

The current Windows build is not Authenticode-signed unless the release runner receives a valid signing certificate. Publishing an unsigned installer is an explicit owner decision.
