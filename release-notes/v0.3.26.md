# Jarvis v0.3.26

Cumulative Windows release containing the complete v0.3.25 application and the additional audited reliability and manual Self-Repair fixes below. Install v0.3.26 directly; intermediate releases do not need to be installed first.

## Manual Self-Repair

- Bind GitHub approval, branch reuse, CI, merge and release checks to the exact repository, PR, branch, approved diff and commit, including externally merged PRs.
- Prevent an older analysis or proposal from replacing a newer request. Recheck the source fingerprint and invalidate pending analyses when an approved repair begins.
- Persist a repair plan before presenting it as pending, restore its exact patches after restart and show the original/replacement content or full new file in the approval view.
- Reject empty repairs and unsafe full-file replacements generated from partial source excerpts.
- Preserve the sensitive-context flag through both AI requests, even when the diagnostic admin session expires while a request is in progress.
- Include production dependency auditing in local repair validation. Keep owner approval, signed core rules, protected source boundaries, backups, validation and rollback checks.
- Correct the actual application source map: include late imports and the Electron preload edge, and prioritize explicitly requested files within the analysis budget.
- Write repair plans and settings atomically. Keep the primary app single-instance while allowing the separate elevated helper handshake.

## Installer updates

- Fix installer script marker selection for LF/CRLF and paths containing spaces.
- Coalesce concurrent update requests, use separate temporary directories and wait for installer-launch errors before closing Jarvis.
- Preserve non-ASCII Windows paths with a UTF-8 BOM in the PowerShell handoff and verify the native handoff on Windows.

## Conversation storage and offline recovery

- Prevent delayed chat results from updating a different or newly created conversation.
- Serialize online and offline history writes, retain the offline conversation identity and merge stored message/attachment history without dropping newer data.
- Confirm IndexedDB transaction completion before acknowledging writes and reject stale queue-worker updates.
- Keep the 200-message archive and 50-message visible window consistent.
- Retry failed legacy/native imports without falsely marking migration as complete, including concurrent attempts and already recovered archives.
- Report unavailable, corrupt or quota-exhausted browser storage explicitly.
- Retain conversation deletion markers across SQLite restart, prevent queued history from recreating deleted conversations and keep deletion metadata out of exports and dashboard counts.

## Voice and device lifecycle

- Isolate recorded microphone and speech-synthesis callbacks by generation so stale work cannot stop a newer recording or reply.
- Settle speech cancellation correctly, separate warm-up timeouts from active replies and honor transcript-queue pause during an ongoing drain.
- Reject unsupported device toggles and missing IoT bridges; scenes and routines cannot report completion when a required device action fails.

## Verification and unsigned publication

The release is published only from the exact successful main-branch Windows build after CodeQL, complete source parsing, the complete source-test suite, lint, typecheck, production dependency audit, the 16 signed-rule verification, renderer build, Self-Repair toolchain staging, NSIS installer build, packaged toolchain checks, admin-helper handshake, Windows startup smoke test, SHA-256 and release-manifest verification.

The installer and release now require a successful security result from GitHub's trusted CodeQL application at the exact commit. Successful execution of the scanner cannot bypass reported security findings, and its SARIF diagnostics remain available for review.

The owner explicitly approved publishing this installer without Authenticode signing. The installer is accompanied by its SHA-256 checksum and release manifest; the unsigned exception does not bypass the other release checks.

The full owner-operated AI → GitHub → elevated installation cycle and physical microphone/device behavior still require hands-on acceptance testing. Automated checks do not establish those live-hardware results.
