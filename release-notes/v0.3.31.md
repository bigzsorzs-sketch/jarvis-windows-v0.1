# Jarvis v0.3.31 — Windows financial workflows and Gmail connector

Candidate update based on v0.3.30. Publication requires the exact candidate's Windows checks; live provider and device acceptance is still a separate requirement.

- Connects paid retail sales, stock and linked company income in one SQLite transaction. Corrects discounted-sale profit by subtracting the full goods cost.
- Adds persistent operation receipts, stale-stocktake protection and compensating returns. Protects linked ledger records from independent edits/deletion.
- Derives invoice totals from validated items; payment creates income once and locks the paid invoice. Creating an invoice does not imply payment.
- Business summaries use current-month GBP cash movements, with unassigned company money identified separately. Refuses invalid dates, money precision and unsupported currencies.
- Implements native Google Desktop OAuth with loopback/state/PKCE, verified account identity, encrypted token storage, refresh and disconnect. The owner must configure a Google client and enable/grant Gmail access.
- Fetches inbox metadata and sends MIME messages with actual PDF attachments. Native sensitive-data confirmation remains required. Provider message IDs are required for send success; uncertain deliveries are not automatically repeated.
- Separates mail-client draft handoff from actual Gmail sending and removes nonfunctional Gmail management buttons.
- Adds actual NSIS install, packaged screen/native financial workflows, restart/persistence and uninstall to Windows CI. Saves an acceptance report and screenshot before checksum generation.

Automated OAuth/AI tests substitute external providers and do not send real email or physical-device commands. See [the acceptance guide](../docs/windows-product-acceptance.md) for live Gmail/voice/device requirements and legacy-data reconciliation. Native mobile packaging, CGM connection, cloud sync and closed-app notifications are not completed by this candidate.

## Verification

- Adds real SQLite financial transaction, rollback, replay, stocktake, return, currency and invoice-payment regression cases.
- Adds loopback OAuth, token refresh/cancellation, metadata, MIME/PDF and duplicate/uncertain send cases, with external Google endpoints substituted.
- Exercises generated invoice PDF bytes through the actual email tool and distinguishes a draft from a send.
- Requires CodeQL, source tests/parsing, lint, the existing limited TypeScript checks, production dependency audit and signed-core-rule verification.
- The exact candidate must pass the Windows native install/build/packaged checks and the new real NSIS install/workflow/restart/uninstall test before an installer is handed over.
- Live Google consent/send, voice/audio and physical-device checks remain separate acceptance evidence; automated tests do not establish them.
