# Jarvis v0.3.21

Windows x64 desktop release candidate, built from an integrated, tested source branch.

## Changes
- Self-Repair: expiring, source-bound proposals; native owner confirmation; serialized apply requests; backup and rollback; full source, lint, type, policy, regression and renderer-build checks before activating a repaired runtime.
- Safer restart and fallback behavior after failed repairs; improved diagnostic boundaries that reject links to files outside the approved workspace.
- Chat history: independent save queues per conversation, preserved text content, clearer offline messaging and more predictable recovery.
- Offline sync: atomic compare-and-swap queue updates that prevent an old sync attempt from deleting a newer snapshot; retries preserve failed data for recovery instead of silently dropping it.
- File uploads and analysis: main-process Base64 validation, limits of 25 MB per batch, and bounded ZIP/DOCX parsing with additional malformed-input tests.
- Electron permissions: reject requests from untrusted windows or origins.
- Backup restoration: attempt restoration of original settings and database on failed import, and report rollback failures.
- Release controls: main-only manually approved publication, checksum and version verification, explicit Authenticode status reporting and version-specific release notes.

## Verification
The integrated 0.3.20-based candidate passed 233 automated tests, parsed 423 source files and passed the Windows installer build, packaged toolchain checks and startup smoke test in GitHub Actions run #638.

**The v0.3.21 package itself must pass a NEW, commit-specific Windows build before publication.** A successful short startup smoke test does not establish correct microphone, OpenRouter, user-facing Self-Repair or long-running behavior.

## Important limitations
- A valid Authenticode signature is preferred. An unsigned public release requires a separate, deliberate owner decision; GitHub SHA-256 hashes alone are not equivalent to a trusted publisher signature.
- The UI and actual Windows desktop behavior still require manual acceptance testing.
- Offline attachments preserve metadata; large file contents need to be attached again when restoring a conversation.
- Very large or maliciously crafted archives may need additional isolation beyond size limits.
