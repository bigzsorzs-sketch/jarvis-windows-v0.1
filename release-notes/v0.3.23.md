# Jarvis v0.3.23

Conversation and Self-Repair reliability update for the Windows desktop application.

- Make ordinary typed and voice conversation requests use the conversation-origin path so sensitive words no longer trigger the external-AI confirmation dialog on every normal chat turn.
- Raise the chat attachment profile to 20 files/images with a 1 GiB selected-data ceiling, including client-side image optimization before the existing Electron transport boundary.
- Add attachment support to the command-center chat input and retain metadata for up to 20 conversation attachments in history and offline snapshots.
- Render the chat history drawer above the desktop navigation layer so it is no longer hidden behind the left sidebar.
- Fix Self-Repair plan persistence so the manual repair workspace is defined and validated before a plan is saved.
- Recognize natural Hungarian repair commands such as “végezd el a javítást” and “hajtsd végre a javítást” so an explicit repair request can produce a pending repair plan.
- Make the visible “Elfogadom / Accept” button the final owner approval for the exact hashed repair proposal while preserving owner-role, expiry, source fingerprint, backup, validation, rollback and restart protections.
- Keep the System Center route grouped under Tools in mobile navigation.
- Move Tailwind-only tooling out of production dependencies so the production dependency audit does not ship the vulnerable build-only braces/chokidar chain.
- Replace wording-sensitive Self-Repair UI tests with behavior checks for the pending hash, apply IPC, rollback handling and disabled-state gating.

## Verification

This release candidate must pass CodeQL, the complete source-test suite, lint, typecheck, production dependency audit, Jarvis policy verification, renderer build, packaged Self-Repair toolchain checks, admin-helper handshake and Windows startup smoke test before publication.

Actual microphone, external AI provider, large real-world attachment uploads and repeated Self-Repair cycles still require manual acceptance testing on a Windows machine. Unsigned installers do not establish trusted publisher identity.
