# Jarvis v0.3.30 — Verified Workflows and File Upload Integration

Cumulative Windows update based on v0.3.29.

## Multi-step chat and voice workflows

- Fixes the undeclared planner source variable that prevented real plans from being requested.
- Routes multi-step chat, voice and live requests to the planner before single-intent commands and voice fallbacks.
- Validates plan status, step count, IDs and parameters. Empty plans and unverified completion claims no longer report success.
- Resolves later parameters from verified earlier results, such as the newly created invoice ID used for PDF generation.
- Stops dependent steps after a failure or cancelled approval and retains previously completed results if the provider becomes unavailable.
- Reuses successful receipts during recovery. Completed writes are not blindly repeated, and only explicitly classified read-only tools may retry transient failures.
- Requires explicit tool acknowledgements for successful execution, summaries and operational memory. Required result fields can distinguish an email draft from an actual send or a cached device state from live verification.
- Enforces disabled capabilities at the executor boundary as well as in the planner.

## AI screen responses

- Quick actions, translation, retail analysis and ecosystem analysis display the actual answer text from the native LLM response.
- Provider failures display a readable message and release the busy indicator.

## Validated uploads and image tools

- Connects image enhancement, mask editing, outpainting, style transfer, multi-image attachments, canvas uploads and finance receipt scanning to the same FileReader/native-validation adapter.
- Removes incompatible FormData/raw-file calls to the data-URL validator.
- Refused uploads do not proceed to AI generation or receipt analysis.
- Enables style transfer on the default layer target without requiring a mask and selects a visible source layer.

## Scope and remaining integration work

Gmail OAuth/send, consolidated retail/finance accounting, native Android/iOS packaging, cloud sync and closed-app notifications still need further implementation. OBD, smart-home and CGM integration require real device validation; direct CGM connection remains disabled. This release does not claim that every module or external service has been validated on physical hardware.

Responsive layouts and touch controls remain the existing foundation for a future mobile port. Recorded STT/TTS use the configured native OpenRouter bridge; this is not a completed standalone mobile voice service.

The detailed findings and acceptance work are recorded in `docs/integration-review-2026-10-08.md`.
